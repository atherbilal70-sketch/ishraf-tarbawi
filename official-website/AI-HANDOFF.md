> الهدف من هذه الوثيقة: أن يَفهم من يُكمل العمل **كل تفصيلة** في الموقع ويعرف **ما يجب ألا يكسره**،

## 1) نظرة عامة

- **ما هو:** موقع حكومي رسمي عربي (RTL) لـ **مديرية الإشراف التربوي** في **وزارة التربية العراقية**.
- **أبرز ميزة:** **بوابة شكاوى إلكترونية** (استمارة + رفع صورة الهوية + رقم تتبع + استعلام عن الحالة) ولوحة إدارة للموظفين.
- **الطابع:** رسمي، نظيف، متجاوب، بألوان الهوية (أزرق كحلي + ذهبي + أبيض/رمادي).
- **حالة التشغيل:** الواجهة الأمامية **تعمل بالكامل الآن** (الاستمارة بوضع تجريبي محلي). الباكند **جاهز كمصدر** لكن يحتاج نشراً على Cloudflare لتفعيله فعلياً.

- **الباكند:** Cloudflare Worker + D1 (قاعدة بيانات SQLite) + R2 (تخزين مرفقات).

## 6) ⚠️ القواعد الحرجة — «لا تكسر هذا»

هذه أهم قسم. أغلب هذه القواعد نتجت عن أخطاء حقيقية حصلت وأُصلحت:

1. **بناء Tailwind إلزامي بعد أي تعديل على الكلاسات.** Tailwind مبني محلياً وليس CDN. إذا أضفت أي كلاس Tailwind جديد في HTML/JS أو عدّلت `tailwind.config.js`، **يجب** إعادة البناء وإلا لن يوجد الكلاس في CSS:
   ```bash
   cd official-website && npm install && npm run build:css
   ```
   (CDN الخاص بـ Tailwind محجوب في بيئة الإنتاج، فلا تعتمد عليه.)

2. **لا تجمع `hero-pattern` مع `bg-gradient-to-*` من Tailwind على نفس العنصر.** كلاهما يضبط `background-image`، و`hero-pattern` (المحمّل لاحقاً) **يُلغي التدرّج** فيصبح نص أبيض على خلفية فاتحة (كان هذا عطلاً حقيقياً). للخلفيات الكحلية المتدرّجة استخدم `hero-navy` / `hero-blue` / `hero-green`.

3. **الكلاسات اللونية المخصّصة** مثل `from-[#215079]` تعمل فقط إذا كانت موجودة في ملفات `content` وقت البناء (أُعيد بناء Tailwind). لا تضف ألواناً عشوائية دون إعادة بناء.

4. **RTL:** استخدم الخصائص المنطقية (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `inset-inline-*`) **وليس** `left/right`. اللغة عربية والاتجاه من اليمين لليسار.

5. **شريط التنقل والتذييل موحّدان عبر كل الصفحات.** إذا غيّرت رابطاً أو عنصراً في القائمة أو التذييل، **غيّره في كل الصفحات الثماني بنفس الشكل** (index, about, news, results, contact, faq, forms, complaints) — وإلا يصبح الموقع غير متّسق. (القائمة = `nav` سطح المكتب + `#mobile-menu` للهاتف.)

6. **ترتيب تحميل الأنماط ثابت:** `tailwind.css` ثم `site.css`. `site.css` يَغلِب. لا تعكس الترتيب.

7. **`assets/css/tailwind.css` مولّد — لا تُعدّله يدوياً.** عدّل `site.css` للتنسيقات المخصّصة، أو `tailwind.config.js` + أعد البناء.

8. **رسائل الخطأ في الاستمارات (`.err`) تستخدم `visibility` مع مساحة محجوزة** (ليس `display:none`). تحويلها لـ `display:none` يُعيد عطلاً في النقر/القفز. لا تغيّر هذا.

9. **أزرار اختيار «صفة المشتكي»** تستخدم نمط تراكب `.role-input.peer` (زر راديو شفاف يغطي الرقعة)، وليس `sr-only`. لا تُرجعها لـ sr-only (تسبب قفز تمرير).

10. **الوضع التجريبي مقابل الحقيقي:** `config.js` فيه `API_BASE`. فارغ = الاستمارة ولوحة الإدارة تعملان **تجريبياً بحفظ محلي (localStorage)**. ضع عنوان الـ Worker المنشور لتفعيل الباكند الحقيقي.

11. **لا تختلق محتوى حقيقياً وتنسبه لأشخاص حقيقيين.** الأرقام/الأخبار/المنشورات الحالية **بيانات توضيحية (placeholder)**. تحديداً: لا تختلق منشورات أو أقوالاً وتنسبها للمدير العام **م. م. عمر عبد الكريم المشهداني** — تُضاف فقط من مصدرها الرسمي.

## 7) كيف تعمل كل صفحة

- **index.html:** سلايدر 3 شرائح (تلقائي + أسهم + نقاط)، قسم «المدير العام» (بطاقة + رابط فيسبوك)، «عن المديرية» (3 كروت)، إحصائيات متحركة عند الظهور، «خدماتنا الإلكترونية» (4 بطاقات روابط)، معاينة الأخبار (فلترة + تكبير)، معاينة النتائج (بحث/فلترة)، دعوة للشكاوى.

- **news.html:** بحث نصي + فلترة تصنيف (أخبار/ورش/تقارير/ندوات) + نافذة تكبير للبطاقة.
- **results.html:** جدول قابل للبحث والفلترة (منطقة/سنة). أزرار «تحميل PDF» تجريبية.
- **contact.html:** 4 بطاقات معلومات + نموذج استفسار يُنشئ رسالة بريد عبر `mailto` (بلا خادم).
- **faq.html:** أكورديون أصلي عبر `<details>/<summary>` (لا JS).
- **forms.html:** كروت نماذج (PDF/DOCX)؛ أزرار «تحميل» تُظهر تنبيهاً تجريبياً حالياً.

- **admin.html:** شاشة دخول (عنوان API + مفتاح)، بطاقات إحصائية، جدول شكاوى مع فلترة/بحث/ترقيم، نافذة تفاصيل (تغيير حالة، تنزيل الهوية، سجل تدقيق)، تصدير CSV.

## 8) ملفات JavaScript

- **`main.js` (كل الصفحات):** قائمة الهاتف، ظل شريط التنقل عند التمرير، تحديث سنة التذييل، السلايدر، عدّادات الإحصائيات (IntersectionObserver)، فلترة+بحث الأخبار، نافذة تكبير الخبر، بحث/فلترة جدول النتائج، ومعالِج التنزيل التجريبي `[data-demo-download]`.
- **`complaints.js`:** تحقق من الحقول (في المتصفح — تجربة فقط)، رفع الملف بالسحب والإفلات مع تحقق النوع/الحجم، عدّاد الأحرف، التحقق من Turnstile إن فُعّل، الإرسال: إلى `POST /api/complaints` إن كان `API_BASE` مضبوطاً، وإلا حفظ محلي تجريبي؛ توليد رقم تتبع ونافذة نجاح؛ الاستعلام عن الحالة.
- **`contact.js`:** تحقق + فتح البريد عبر `mailto` برسالة معبّأة.
- **`admin.js`:** المصادقة بترويسة `x-admin-key` (تُحفظ في `sessionStorage`)، تحميل الإحصائيات والقائمة، فلترة/بحث/ترقيم، تفاصيل الشكوى، تغيير الحالة (`PATCH`)، تنزيل الهوية عبر fetch مصادَق + blob، عرض سجل التدقيق، تصدير CSV.
- **`config.js`:** `window.SITE_CONFIG = { API_BASE, TURNSTILE_SITE_KEY }`.

## 9) الباكند (Cloudflare Worker + D1 + R2)

المصدر كامل في `backend/src/worker.js`. **لا يعمل حتى يُنشر على حساب Cloudflare.**

**مسارات الـ API:**
| الطريقة | المسار | الوصف | الحماية |
|---|---|---|---|
| POST | `/api/complaints` | استلام شكوى + مرفق، توليد رقم تتبع | عام (+Turnstile اختياري) |
| GET | `/api/complaints/:ref` | استعلام عن الحالة (بيانات محدودة) | عام |
| GET | `/api/admin/stats` | إحصائيات حسب الحالة | `x-admin-key` |
| GET | `/api/admin/complaints` | قائمة الشكاوى `?status=&q=&page=&perPage=` | `x-admin-key` |
| PATCH | `/api/admin/complaints/:ref` | تغيير الحالة | `x-admin-key` |
| GET | `/api/admin/complaints/:ref/attachment` | تنزيل صورة الهوية | `x-admin-key` |
| GET | `/api/admin/export` | تصدير CSV | `x-admin-key` |
| GET | `/api/admin/audit` | سجل التدقيق `?ref=&limit=` | `x-admin-key` |

**الـ bindings (في `wrangler.toml`):** `DB` = قاعدة D1 باسم `ishraf-complaints` · `ATTACHMENTS` = مخزن R2 باسم `ishraf-id-attachments`.

**المتغيرات/الأسرار:**
- `ALLOWED_ORIGIN` (متغيّر، افتراضي `*` — اضبطه على أصل الموقع في الإنتاج) · `RATE_LIMIT_PER_HOUR` (افتراضي 5).
- أسرار تُضبط بأمر منفصل: `ADMIN_KEY` (إلزامي للوحة الإدارة) · `RESEND_API_KEY` + `EMAIL_FROM` (اختياري للإشعارات البريدية عبر Resend) · `TURNSTILE_SECRET` (اختياري للتحقق البشري).

**الأمان المطبّق:** تحقق كامل في الخادم، فحص نوع الملف بالتوقيع الثنائي (magic bytes) وحد 5MB، تخزين R2 خاص باسم عشوائي (لا رابط علني — التنزيل عبر مسار محمي فقط)، سجل تدقيق لكل اطّلاع/تغيير، تحديد معدل بالـ IP، Turnstile اختياري، CORS.

## 10) كيف تُجري تغييرات شائعة بأمان

- **تشغيل الموقع محلياً:** `cd official-website && python3 -m http.server 8080` ثم افتح `http://localhost:8080`.
- **تعديل التصميم:** عدّل `assets/css/site.css` (مخصّص) أو ألوان `tailwind.config.js` ثم `npm run build:css`.
- **إضافة كلاسات Tailwind جديدة في HTML:** ثم `npm run build:css` دائماً.
- **إضافة صفحة جديدة:** انسخ ترويسة ونفس `<head>` ونفس شريط التنقل والتذييل من صفحة موجودة؛ حمّل `tailwind.css` ثم `site.css` ثم `main.js`؛ أضف الصفحة لـ `sitemap.xml` وفحص CI.
- **إضافة عنصر للقائمة أو التذييل:** طبّقه على **كل** الصفحات الثماني (سطح المكتب + الهاتف) بنفس الصياغة.
- **إضافة خبر:** أضف `<article class="news-card" data-category="news|workshop|report|seminar">` داخل `#news-grid` (الفلترة/البحث تعملان تلقائياً).
- **تفعيل الباكند الحقيقي:** انشر الـ Worker (انظر 11) ثم ضع رابطه في `config.js` → `API_BASE`، وأعد الدفع.

## 11) سير العمل والنشر

**نشر الواجهة (GitHub Pages):**
1. اعمل التعديلات داخل `official-website/`.
2. ادفعها إلى فرع، ثم افتح Pull Request إلى `main`، ثم ادمجه.
3. يُعيد GitHub Pages البناء تلقائياً خلال 1–2 دقيقة. حدّث الصفحة بـ **Ctrl+Shift+R** لتجاوز الكاش.

**CI (في `.github/workflows/`):**
- `website-ci.yml`: يفحص صياغة JS، يتحقق من الـ manifest، يبني Tailwind، ويتأكد من وجود الملفات — يعمل على كل PR/push يمسّ `official-website/`.
- `deploy-worker.yml`: نشر الباكند يدوياً من GitHub (Run workflow) بعد إضافة سرّي `CLOUDFLARE_API_TOKEN` و`ADMIN_KEY` في إعدادات المستودع.

**نشر الباكند محلياً (بديل):** `cd official-website/backend && npx wrangler login && bash deploy.sh` (يُنشئ D1 وR2، يطبّق المخطط، يضبط الأسرار، وينشر).

## 12) بيانات توضيحية يجب استبدالها بالمحتوى الرسمي

- الشعار (حالياً أيقونة SVG نجمة مؤقتة) ← شعار الجمهورية/الوزارة الرسمي.
